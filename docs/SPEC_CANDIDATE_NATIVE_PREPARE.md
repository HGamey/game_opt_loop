# Candidate preparation: supervised native artifact construction

Refs [system #14](https://github.com/HGamey/.github/issues/14) and [epic #11](https://github.com/HGamey/.github/issues/11). Stacked on GOL [#34](https://github.com/HGamey/game_opt_loop/pull/34), consuming PF [#24](https://github.com/HGamey/phonefarm/pull/24). SPEC precedes implementation. The expanded journal is `game_opt_loop/candidate_prepare@2` with six named stages; old @1 sessions require the matching #34 inspector and are not silently upgraded.

## Contract and scope

Retain the actual private GOL compile/replay and PF adapt/replay stages. A requested present SDK can additionally run `gray-artifact build --adapted-artifact ... --ndk SESSION/ndk.snapshot --process-supervision inherited-group`, then a separate bounded `gray-artifact verify` stage. PF executes as the fresh process-group leader created by the existing durable launch/permit wrapper. Every command must exit and the outer observer must prove its group absent before any result is accepted. The builder receipt remains provisional; PF cannot certify outer group retirement. The wrapper re-reads the artifact only after retirement, runs the verifier, proves its group absent, and re-reads all files again.

Native artifact integrity is host evidence. All GPU, semantic, quality, deployability, real-game and promotion flags remain false. `PREPARED_OFFLINE_NATIVE` means the requested host preparation stages completed, not a deployable candidate or a complete evaluation driver. Fake SDK output must be requested with `--synthetic`; it remains `synthetic_mechanism_fixture`, `android_codegen_validated=false`, `real_ndk_validation=not_run`. Tests never install/run a real NDK or execute GPU/device/model commands.

## Explicit inputs and dependencies

Present SDK builds also require `--native-layer-input-root DIR`: one of two exact external PF layer contracts is frozen before launch: `legacy4` (vk_layer_refknobs.cpp, artifact_stats.h, copyprobe_copy.comp, VkLayer_refknobs.json) or `ownership5` (those four plus dispatch_ownership.h). The header must be absent for legacy4 and present as a regular file for ownership5. The declared root may also contain the known unused upop.comp; other entries are refused. Input contract, presence, and all used bytes are frozen, so a newly added/removed header cannot silently change the contract. This option does not redirect PF's compile-time source root. Build acceptance compares the actual descriptor inputs to these expected bytes and rechecks the declared source root after build; wrong roots and source changes are refused. This freezes this builder's declared input set, not arbitrary C++ dependency resolution. The returned descriptor and staged file set must match exactly the selected four/five input contract; unknown extras are refused. Other builder input sets need an explicit compatible contract.

The entire supplied SDK directory is copied into a new private snapshot before any command. Supported layouts contain bounded regular files/directories only: symlinks (including common real-NDK wrapper links), special files, excessive depth/count/bytes and unreadable entries are refused explicitly. Initial limits are depth16, entries4096, per-file512MiB, total512MiB and metadata2MiB. Unsupported layouts are BLOCKED, not reduced to a few convenient executables or replaced by another toolchain. Real NDK compatibility is unaccepted until a real layout/build is separately validated. SDK source paths are never execution paths. Private tree inventory and content hashes are checked before and after native execution and during offline inspect. Read-only permissions are integrity hygiene under a trusted same-user host, not a sandbox or protection against same-user tampering.

The complete regular SDK snapshot captures local files including provided sysroot and libraries, but not system libraries, interpreters, arbitrary absolute paths embedded in scripts, runtime network access, deliberately detached helpers or tool authenticity. Explicitly trusted local tools must not detach from the controlled process group. Tool paths/hashes in PF's actual native descriptor must resolve to the frozen SDK inventory. No environment NDK fallback is allowed.

## Persistence and refusals

Freeze SDK/layer snapshot identity, build policy, actual tools and candidate/source/SPIR-V/adapter identities before executing native tools. SDK preflight refusals are persisted with NOT_RUN native stages and a BLOCKED result; missing caller SDK retains the actual PF refusal against a private empty SDK. The missing caller path is never reused as executable input.

`--native-tool-timeout-seconds 1..120` (default30) freezes the PF per-helper budget independently of the outer stage timer; it cannot extend the stage or whole budget. Native build and native verify use the existing per-stream/wall/whole-budget limits, including SDK copy and post-execution rehash and final publication. Streaming checks the whole deadline between blocks; regular filesystem syscalls and fsync are not a real-time OS sandbox. A result finishing integrity checks or publication after the deadline cannot be accepted. They retain fsynced in-flight/PID journal and atomic permits. Helper timeout/overflow may kill PF itself; signal, missing receipt, surviving descendants (even with closed pipes), output failure and unproven group retirement remain UNKNOWN, never accepted or automatically retried. Offline inspect runs no tools and does not infer quiescence from a receipt string.

Accept only one returned native artifact immediately beneath the owned native output directory. Require inherited mode, provisional state, false deployability/device-not-run, exact descriptor identity and manifest/file set/hash agreement. Bind imported original source/SPIR-V and adapted SPIR-V to the GOL/PF chain; bind the selected four/five layer inputs and each native tool to the private SDK. Record both outer PID/exit/group receipts, frozen SDK/layer inventory hashes, native descriptor/manifest/layer hashes and provisional PF verification result. Inspect reconstructs these bindings from current bytes and rejects rehashed outer receipts that contradict them. Both native nested receipts must equal the parsed, hashed stdout records; build and verify must agree on the original build receipt. Fixed target, shader/native flags, ABI and complete adaptation-origin summary must match the known PF contracts, rather than trusting renamed/rehashed descriptors.

## Acceptance

Run actual local GOL against both the independent PF24 legacy4 builder and the current resource-ownership ownership5 PF builder against an explicitly controlled fake regular SDK, not a fake successful PF compiler. Preserve actual missing-SDK negative. Exercise timeout, full stderr/overflow, successful tools leaving live descendants with closed pipes, executable mutation, SDK/input tampering and rehashed inspect contradictions. Existing four-stage, gate-failure, closed/open-pipe and unknown/no-retry tests remain. Run complete GOL tests and strict clippy; independent review before publishing a stacked draft. Report actual NDK/GPU/device/API calls as zero.
